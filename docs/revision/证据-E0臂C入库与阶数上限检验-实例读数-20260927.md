## 四、E5（同机 CFD 单价）本轮判**未完成**，并抓出一个会让单价表静默偏小的缺陷

- 冷启动容器里 FreeFem **不在**（`command -v FreeFem++` 空）。`tar xzf ffroot.tgz -C /` 之后二进制回来了，但仍缺 4 个 so：`libumfpack.so.5 / libcholmod.so.3 / libarpack.so.2 / libhdf5_serial.so.103` ⇒ 修法：`apt-get install -y libsuitesparse-dev`（补前两个）+ **从 NAS 上的 `ffstage/lib/x86_64-linux-gnu/` 拷 `libarpack.so.2`、`libhdf5_serial.so.103`** + `ldconfig`。**所以"归档取回即跑"这句对冷启动不成立**，复现声明要加这一条。
- 求解器起不来时 `e5_cfd_price.py` 的行为：42 次调用全部 **`rc=127`、`wall=1 ms` 被照常记成一次读数**，一路跑完三工况，**并写出 3,525 B 的 JSON**，直到汇总 `:292` 拿 `row['min_s']` 对空列表取值才 `KeyError` 崩掉。⇒ 若 rc 里混着 0 和 127（例如只有某个工况的求解器名写错），它会**算出一个偏小的中位数单价且不报错**。已把该产物就地隔离：`pinn-repro-2026/out/e5_cfd_price_a0d1375.INVALID_rc127_do-not-cite.json`（sha256 前缀 `f95ec999a8461f95` / 首版 `fc4427f69e58387e` 为第二次）——**不得被任何表引用**。
- 修法要求（派给方案线，见 §五）：`rc != 0` 的那次读数**不进统计**、且 **`rc==0` 次数 < 门槛（建议 ≥5/7）就拒写 JSON 并非零退出**；另加一条"求解器可执行性前置探测"（跑 `--version` 或一个 1 行 `.edp`，起不来就整体退出而非记 1 ms）。
