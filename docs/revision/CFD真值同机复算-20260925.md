## 三、当场发现的缺陷：入库的 `.edp` 不能在任何别的机器上原样跑

- **33 个 `.edp` 里有 32 个把原作者机器的绝对路径写死在输出语句里**（`ofstream fout("/root/dev/pinn_v3/cases/...")` 与 `/root/dev/pinn-platform-v4/model/cases/...` 两种前缀）。
- 后果：换机器直接跑 ⇒ `Error opening file` ⇒ **rc=8**（我第一次尝试就是这样失败的，属设备错不是产品错，但审稿人不会知道差别）。
- 修法（已验证）：一条 sed 即可让任意机器可跑，不必改生成器——
  ```bash
  W=$PWD/route2_out/gen; mkdir -p $W/gen/$(dirname 相对路径)
  sed -E 's#/root/dev/[a-z0-9._-]*/cases#'"$W"'/gen#g' X_stokes.edp > X_run.edp
  FreeFem++ -nw X_run.edp
  ```
  注意：**目标目录必须先 `mkdir -p`**，FreeFEM 不会自己建目录，且它建不出目录时报的是 rc=8 而不是写权限错。
- 生成器本身没这个毛病（`model/src/data/contraction_freefem.py:114`、`bend_freefem.py:165` 用的是 `{raw_csv_path}` 模板变量），**问题只在入库的 `.edp` 快照**。所以正文里"可复现"要区分两件事：① 用仓库生成器重跑 = 可复现；② 用入库 `.edp` 直接跑 = 需要一处路径改写。
- 另一处：**入库 `.edp` 与 `*_raw.csv` 都是 CRLF**（Windows 工作树产物）。直接 `cmp` 会报差异，比对前必须 `tr -d '\r'`。
