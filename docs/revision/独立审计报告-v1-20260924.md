# B. 效率声称公平性审计

> 用户假设："快几倍至几十倍"是因为 PINN 精度不够。审计结论：**方向对，但不是因为分辨率让 PINN 变快，而是（1）精度不同档却互比、（2）训练成本不入表、（3）"几十倍"来自作者给弯曲工况自配的 5 倍重网格、（4）计时的一条线根本不是被评估的那个方法。**

## B.1 分辨率对齐

| 项 | 数值 | 来源 |
| --- | --- | --- |
| PINN 预览网格上限 | `max_samples=112 / min_samples=72` | `api/pinn_platform_api.py:412-429` |
| 收缩 C-base 场景（Ltot*=16，aspect=16）预览实际域内点数 | **6504（其中内部 6108，边界 396）** | 按 `model/src/data/contraction_geometry.py:90-123` 的 `interior_grid` 逻辑本地重算（112×72 格点 + 半宽判定），脚本 `.scratch/audit_data.py` 段 E 同源 |
| full 分辨率点数 | 14094（`max_samples=168`） | 同上重算 |
| 弯曲预览目标点数 | `BEND_PREVIEW_TARGET_POINTS=5600`（full=11000） | `api/pinn_platform_api.py:63-64, 454-463` |
| CFD 求解网格 C-base | **2113 顶点 / ≈3796 三角形 / ≈14.8k 自由度**（P2-P1 Taylor-Hood） | `model/cases/contraction_2d/cfd/C-base/C-base_raw.csv` 行数直数；单元数由欧拉公式估算；`buildmesh(bottomWall(180)+outletEdge(28)+topWall(180)+inletEdge(40))`（同目录 `C-base_stokes.edp:78`） |
| CFD 求解网格 B-base | **10493 顶点 / ≈20058 三角形 / ≈73k 自由度** | `model/cases/bend_2d/cfd/B-base/B-base_raw.csv`；`B-base_stokes.edp:85-97`（22 段/单位长度） |

三点判定：

1. **计时线与打分线不是同一张网**。第 5 章所有误差数字都在 CFD 网格顶点（2113/10493 点，`field_dense.csv` 与 `_raw.csv` 逐案同数）上算；效率数字在预览结构化网格（6504 / ~5600 点）上算。预览分辨率上**没有任何精度测量**，CFD 网格上的推理耗时**没有计时**。所以"快 6–30 倍、误差 2–3%"是两个网格上的两件事，不构成同精度对比（E3）。
2. **修正方向对 PINN 有利，不对它不利**：若把 CFD 细化到与预览同点数，按测得的时间–顶点指数 1.24（由两个实测点 log(7.26)/log(4.97)）估算 CFD 约 2.7–4 s，加速比会更大；若把 PINN 升到 CFD 网格点数，推理约线性降到 0.027 s，加速比 18×。**因此"分辨率不对齐"不是这条声称的破口**，写进反驳里会反被利用。
3. **"几十倍"的真正来源是网格重量**：弯曲 CFD 用 928 段边界（收缩 428 段）、5.0× 顶点。artifact 的 .md 第 22 行原话"主要原因是其 CFD 网格更重、求解代价更高"。把弯曲网格按"单位长度 26.8 段"（=收缩的密度）折算，顶点 ≈2565、CFD ≈0.64 s、**加速比 30.7× → 5.4×（审计外推，需团队复核）**。论文删掉了归因句，把它写成"提升效果十分显著"。

## B.3 加速那一侧的精度：误差与耗时同列

| 计时线 (s) | 对应模型的误差（同一 run） | 坐标 |
| --- | --- | --- |

物理换标：p 尺度 = μU/W = 4.451e-4 Pa/单位 p*（`meta.json` 的 rho/mu/U/W），故 C-test-2 压降误差 33.31% = **0.29 Pa**，真值压降 0.87 Pa。

判定 **"适合设计早期筛选"（1256、1260）**：筛选用的正是压降排序。本地复算显示模型对压降是**系统性压平**——3 个工况真值 638/1069/1958（3.07×跨度），strict 模型预测 661/952/1214（1.84×跨度，**压缩 40%**：低值高估、高值低估）。在这 3 个点上排序没有翻转（审计核验），但：
- 只有 3 个设计点，无法给出"排序可靠"的结论；仓库没有 β 网格扫描下的预测压降序列（train 工况的预测未落盘，各 run 只评估 val/test 3 个工况）；
- 一旦两个候选设计的真实压降差 <40%，压缩就会翻序；
- 更致命的是**基准选错**：同一份真值场，一个零训练零数据的解析式（局部 Poiseuille + 润滑压降 `dp/dx=-12/W(x)^3`）在本几何族上给出 u/p 相对 L2 **0.0007–0.0014、压降误差 0.0005–0.0009**（`.scratch/audit_analytic.py`，指标定义与仓库 `mean_rel_l2_*` 一致）。也就是说，"筛选用的压降"能被一行公式以 0.05–0.09% 误差、微秒级耗时拿到。
- 弯曲族上该解析式（只用壁距）速度误差 0.0143–0.0323（`.scratch/audit_bend.py`），与论文报的 0.020–0.028 同量级、部分更优。

→ 结论：**"快几倍到几十倍"这句话即使数字全部成立，也不能支撑"因此适合筛选"**，因为在筛选所需的量上存在一个又快又准得多的免费基线。用户的假设（精度不够使对比不公平）在收缩族被证实（33% 压降误差 vs 0.05% 解析），但破口是"精度档位不同 + 存在免费更强基线 + 训练不入账"，不是"点数少"。

## B.4 参数化复用是否真实

- **真实**：每个模型确为多工况训练，`train_cases` = 6 个收缩工况（`…mainline_v4/config.json#train_cases`）、弯曲 4 个（`…20260419` 系列）；不是每工况单练。API 可接受任意 β/Lc（`api/pinn_platform_api.py:366-400`）→ 复用链路存在。
- **但边界比论文写的紧**：
  1. 族内且**宽度固定、低 Re、抛物入口/指定剖面**；弯曲按入口剖面分了 4 个模型（parabolic / skewed_top / skewed_bottom / blunted），换剖面即换模型；
  2. **收缩与弯曲不能同模型**：`family` 为单选，特征集不同（15/14 列，表2-5 vs 表2-6），仓库 41 个 config 的 family 取值只有 `contraction_2d`/`bend_2d`（本地汇总 `.scratch/audit_runs.py`），无任何跨族模型；
  3. **无参数域守卫**：API 对 β、Re、W 不做范围检查（`:366-400` 只有黏度上下界用于反演），把域外输入当域内用；论文 5.6 已示域外（C-test-2）压力误差 31%。
- 另注：`表3-3` 把 B-test-2（θ=60°）列为"转角泛化测试工况"，但双模型主线从未评估它（仓库中仅出现在早期单网络监督 run `results/supervised/bend_supervised_geometry_v1_20260331/evaluations/metrics_test.json`：速度 0.0627 / 压力 0.201 / 压降 0.1123）。**转角泛化这一维实际未被测。**

## C.3 壁面残余速度：构造保证，非学习成果

`train_velocity_pressure_independent.py:184-196`：`envelope = (1 - exp(-k·d)) / (1 - exp(-k))`，k=12，`d = clamp(wall_distance_frac, 0, 1)`；`:210-214` 把物理空间速度整体乘上该包络。因此 d=0 ⇒ 输出**恒等 0**，与网络权重无关。

产物核验（`.scratch/audit_data.py` 段 C）：C-val 的 360 个 wall 行中 **298 行 `u_pred` 精确等于 0.0**；余下 62 行的 `wall_distance_star` = 1.000000000001e-06（即包络≈1.2e-5，非零仅因浮点残值）。同 run `history.csv` 第 2 行"壁面损失=3.71e-11"（权重本来就是 0）。

**第一问："线性的 Stokes 问题，为什么需要 PINN？"——诚实回答**

1. 唯一能显示"物理约束有增量"的实验是 0% 观测（无任何内部观测点，仅靠 PDE + 边界）：速度误差 0.3004，而 1% 观测即降到 0.0296、5% 到 0.0275（`docs/ablations/bend_zero_supervision_20260420/bend_zero_supervision_summary.md`）。它证明的是"有几十个观测点就够了"，**不是"需要 PINN"**。
2. 与"不需要 PINN"的两个基线比：零训练解析式在收缩族上 u/p 误差 0.0007–0.0014；同点数插值在压力上 0.0224（模型 0.0685）。两者都比模型准（B.3、D.4）。
3. 与同规模的单网络监督基线比，模型的内部流体精度更差（C.1–C.4）。

# I. 总体定位（三句）

1. **档位**：按现有证据，这是一份**应用型本科毕设中上水平的系统/演示工作**——链路完整、产物可核、限定语偶有诚实之处；但它**不是**可发表的方法贡献，也**尚未达到**"合格即无保留"的标准，因为两条创新点所依赖的对照在仓库内是可反驳的（第 0 节 #1、#2）。
2. **三条一审就撑不住的声称**：① "双模型 PDE 耦合优于单网络/有效避免干扰"（内部点复算方向相反，壁面增益来自构造）；② "几何增强编码使压力误差由 11.76 降至 0.15"（双变量消融，同仓库干净对照给 0.27→0.18）；③ "PINN 比 CFD 快几倍到几十倍、适合设计早期筛选"（训练不入账、网格密度不等、精度档位不等，且零训练解析式在筛选所需的压降上准 100–600 倍）。
3. **只能留一个卖点，就留"参数化几何 + 构造化边界 + 全链路可复现的演示系统"**：多工况训练确实存在、无量纲复用确实跑通、API/前端/产物完整，这是唯一不需要新实验就能守住的贡献。要让它站得住，需要补的测量只有三项，且都很便宜：(a) 在**同一 CFD 网格分辨率**上重跑计时，并把 98.8 s 训练与拐点写进同一张表；(b) 补两个零训练基线（解析润滑式 + 同点数插值）与"单网络联合 PINN"一臂，把"净增量"重算一遍；(c) 关键表格 ≥3 个 seed，给出 mean±std（需 scipy）。若只做一件，做 (a)——它决定第 5 章效率一节是保留还是删除。
