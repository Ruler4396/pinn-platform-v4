1. **表里那一行的 `0.029925` 是 n=11，配对差用的不是它。** 稀疏档两条配对只用 `obs_seed=0` 的五粒，这五粒的双模型均值 = **0.031202 ± 0.004515**。两条独立配对反推出同一个 0.0312020（`0.023144+0.008058`、`0.051029−0.019827`），我另按产物 `values` 的索引集 `{0,4,8,9,10}` 复算到逐位一致 ⇒ 不是抄错。**后果**：若表里并排放"0.029925"与"−0.008058"，审稿人一句"这两个数不是同一批"就能打掉整行。⇒ 二选一：**(甲)** 该行改用 `0.031202 ± 0.004515 (n=5, obs_seed=0)`，与配对差同源；**(乙)** 保留 n=11 值，但在同格并写 `配对所用五粒 = 0.031202`。**（顺带：子集 sd 与 11 点 sd 到第 6 位巧合相同（0.004515117 vs 0.004515110），不是复制粘贴错。）**
2. **`analyze_t4_full.json` 里 `cells.*.values` 的数组顺序 = run 目录名排序，不是 `pair_keys` 顺序**（t5c04 的 `s42__o0/o1/o2/o3` 排在前面）。⇒ 按"前五个当 obs_seed=0"会算成 0.032537（我第一遍就错在这里）。引用坐标请指 **keys 或索引集**，不要指"第几行"。
3. **臂 B 在 `pooled` 口径下结构上没有配对**：`P3/P5 n_pairs=0`、双模型侧 5 个键全落 `orphan_b`。⇒ 表只能用 `mean_of_cases`；若别处写"两口径都跑了"，臂 B 这两行必须另注 pooled 无对，不然又是一处口径与覆盖不一致。
